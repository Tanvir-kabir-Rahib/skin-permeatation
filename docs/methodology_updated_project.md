# Methodology

This methodology describes the current implementation in the skin-permeation repository. The Abdallah et al. paper is treated only as a broad reference for academic organization and presentation. Its dataset sizes, descriptor counts, model rankings, validation results, cluster assignments, and conclusions are not used as evidence for the methods described below.

## 1. Study Design

The project develops quantitative structure-permeability relationship models for predicting skin permeability, expressed as `logkpl` (LogKp), from molecular structure, permeation temperature, and calculated molecular descriptors. The implemented workflow comprises: (1) curation of experimental permeability records and molecular identifiers; (2) calculation and validation of Chemistry Development Kit (CDK) descriptors; (3) removal or imputation of unusable values, duplicate rows, and redundant descriptors; (4) development of baseline, benchmark-optimized, grouped-validation, and validation-ready model sets; (5) evaluation using holdout and cross-validation metrics; (6) prediction for DrugBank compounds without experimental LogKp labels; (7) applicability-domain, principal component, and clustering analyses; and (8) prediction of LogKp for user-supplied SMILES through an RDKit-assisted inference workflow.

The repository contains several modeling tracks that answer different methodological questions and should not be treated as one interchangeable analysis:

1. The paper-style baseline track reproduces the earlier 85:15 random-split workflow for comparison.
2. The benchmark track retains a random row split but applies train-fitted filtering, feature selection, and model search.
3. The improved track uses a grouped holdout based on SMILES to prevent the same molecular structure from occurring in both the training and holdout partitions.
4. The later validation-ready workflow selects a model from training-only out-of-fold predictions and evaluates it on a held-out partition using extended QSAR/QSPR metrics.

The grouped workflow provides the most direct implemented assessment of generalization to previously unseen SMILES. However, the checked-in extended validation artifacts were generated with the paper-reproduction random-split protocol rather than the available strict grouped protocol. These two results are therefore reported separately.

## 3. Data Cleaning and Preprocessing

### 3.1 Experimental data preparation

The retained workflow and audit artifacts document the following sequence:

1. The descriptor-generator documentation records prior curation of salts, water records, and hydrates. It states that four salts and 31 water results were removed and that two hydrates were converted to their anhydrous forms. The original source-stage implementation of all these manual decisions is not retained.
2. The current preprocessing utility `remove_water_rows` removes rows with indices 445 through 475 from the 476-row source, producing the 445-row `trial4.csv` stage.
3. Missing `topoShape` values are assigned the arithmetic mean. Missing `HybRatio`, `JPLogP`, and `Kier3` values are assigned their medians. The checked-in `trial4.csv` has no remaining missing cells.
4. Exact duplicate rows are removed. This reduces the table from 445 to 417 rows by deleting 28 duplicates.
5. `Compound` and `SMILES` are retained as identifiers but excluded from the numerical model matrix. `logkpl` is separated as the response.

The function `reconstruct_clean_trial4` additionally removes eight manually specified columns (`khs.ssssB`, `khs.ssssBe`, `SCH-4`, `C1SP1`, `khs.tsC`, `khs.sssNH`, `khs.sI`, and `SCH-3`) and applies absolute Pearson-correlation filtering at 0.95. A direct audit found that this current function produces 150 columns, whereas the checked-in `clean_trial4.csv` contains 149 columns and a partly different set of retained correlated descriptors. The final CSV is therefore treated as the authoritative input to all saved model artifacts.

### 3.2 Molecular component, salt, and charge handling

The Java CDK code parses each SMILES string and checks molecular connectivity. For a disconnected representation, such as a salt or hydrate, it partitions the structure into components and retains the component with the greatest number of bonds. Formal charges on the retained component are temporarily set to zero, atom types are perceived, and the stored charges are restored when an unknown atom type requires a second perception attempt. Implicit hydrogens are added and, in descriptor generation, converted to explicit hydrogens before aromaticity and ring processing.

This is a largest-fragment rule rather than a comprehensive medicinal-chemistry standardization protocol. No RDKit MolStandardize workflow, tautomer normalization, stereochemical normalization, or explicit inorganic-compound classifier is implemented.

### 3.3 DrugBank cleaning

The raw DrugBank descriptor table contains 5,031 missing cells. The retained audit and direct comparison of the raw and processed tables show that:

1. Rows missing either `ATSc1` or `BCUTw-1l` are removed. The union of these conditions removes 33 compounds, reducing 2,326 rows to 2,293.
2. `geomShape` is removed.
3. Missing `JPLogP`, `HybRatio`, and `Kier3` values are median-imputed.
4. The resulting `drug_bank_clean.csv` contains no missing cells.

For DrugBank prediction, `Texpi` is not available and is assigned a constant value of 310 K.

### 3.4 Train-fitted preprocessing

The improved pipeline applies median imputation and zero-variance removal within a scikit-learn `Pipeline`. Standard scaling is added only for MLR, Lasso, and RBF-SVR. The benchmark pipeline fits correlation filtering and mutual-information feature selection on training folds. Robust scaling is used for ElasticNet and RBF-SVR in that track. The validation-ready workflow uses median imputation for all candidates and standard scaling for RBF-SVR.

The paper-style baseline intentionally preserves global standardization before splitting. That track is retained for reproduction only because fitting the scaler on all rows exposes holdout-distribution information.

## 4. Molecular Descriptor Calculation

Molecular descriptors are generated with Java 18 and the Chemistry Development Kit, CDK version 2.8, through `descriptors-generator/src/main/java/org/rami/dg/DescriptorsGenerator.java`. Maven dependency and compiler settings are defined in `descriptors-generator/pom.xml`.

The generator:

1. reads `data-original.csv`;
2. parses the `SMILES` field;
3. applies largest-fragment handling to disconnected structures;
4. configures atom types and hydrogen counts;
5. applies legacy CDK aromaticity perception and ring marking;
6. calculates a broad panel of one-dimensional and two-dimensional descriptors; and
7. writes `SMILES`, `Texpi`, and descriptor values to `data-descriptors.csv`.

The descriptor panel includes lipophilicity and polarizability measures, acidic and basic group counts, aromatic atom and bond counts, atom counts, autocorrelation descriptors, BCUT descriptors, carbon-type counts, connectivity and chi indices, eccentric connectivity, molecular distance-edge descriptors, Kier-Hall atom types, hydrogen-bond counts, hybridization ratios, kappa indices, molecular weight, topological polar surface area, rotatable-bond counts, ring descriptors, weighted paths, XLogP, and Zagreb indices.

If CDK does not return a descriptor value, the generator writes `NaN`. Repeated identical SMILES are cached so that the descriptor vector is reused. The raw generated file contains 225 columns: `SMILES`, `Texpi`, and 223 descriptor outputs. The final supervised matrix contains 145 retained molecular descriptors plus `Texpi`.

The inventory utility reports 53 CDK class-name occurrences because its regular expression also detects class names in commented Java lines. The generated column count is therefore the more reliable measure of the executed descriptor panel.

## 5. Feature Engineering and Feature Selection

Feature treatment differs by modeling track.

### 5.1 Final-table descriptor pruning

The checked-in final table reflects exact-duplicate removal, manual descriptor exclusion, and high-correlation pruning. The intended correlation threshold is `|r| >= 0.95`. Because the current reconstruction function does not reproduce the final column set exactly, the saved 146-input schema in `clean_trial4.csv` is used for all current analyses.

### 5.2 Baseline feature selection

The multiple linear regression baseline uses forward sequential feature selection to select 10 inputs. Selection is based on five-fold cross-validated negative MAE. Other baseline models use the full final input matrix.

### 5.3 Benchmark feature selection

The benchmark pipeline applies a train-fitted correlation filter followed by `SelectKBest` using mutual-information regression. The general benchmark configuration searches among 40, 60, 80, 100, 120, or all retained features and correlation thresholds around 0.95 to 0.98.

Inspection of the current saved CatBoost benchmark model shows parameters consistent with the aggressive configuration: correlation threshold 0.99, mutual-information seed 28, and `k="all"`. Thus mutual information was evaluated, but no additional top-k reduction was applied to that selected CatBoost artifact.

### 5.4 Improved-track feature handling

The improved pipeline applies median imputation and `VarianceThreshold(0.0)`. It does not implement recursive feature elimination, SHAP-based selection, or PCA as part of supervised model fitting. `descriptor_family_ablation_plan.csv` inventories descriptor families for possible ablation analysis, but it is a plan/table rather than results from fitted ablation experiments.

### 5.5 Publication-figure descriptor cleaning

`scripts/regenerate_project_figures.py` independently prepares a plotting matrix by excluding identifiers and target/leakage columns, coercing sufficiently numeric columns, and removing all-missing, constant, and exact duplicate columns. For the current figures this produced 99 varying plotting descriptors from the 146-input model matrix.

## 6. Dataset Splitting and Validation Strategy

### 6.1 Paper-style baseline

The baseline uses an 85:15 random row split with `random_state=1`. The scaler is fitted before this split to reproduce the earlier workflow. Five-fold cross-validation is then applied to the training partition without shuffling.

### 6.2 Benchmark track

The benchmark uses a random 85:15 row split. The default `benchmark.yaml` specifies seed 2025, five folds, three repeats, and 40 randomized-search iterations. However, the current saved benchmark model parameters are consistent with `benchmark_aggressive.yaml`, which specifies split seed 22, three folds, one repeat, one sampled parameter setting, no target transformation, and no newly generated ensemble comparison. Preprocessing remains inside the fitted pipeline.

### 6.3 Improved grouped track

The improved track uses `GroupShuffleSplit` with SMILES as the grouping variable, a 15% holdout fraction, and `random_state=2024`. The checked-in split contains 357 training rows representing 124 unique SMILES and 60 holdout rows representing 22 unique SMILES, with no SMILES overlap between partitions.

Hyperparameter search uses five-fold `GroupKFold` on the training data and optimizes negative MAE. The subsequent `cv_mae` reported by `evaluate_regressor`, however, uses ordinary unshuffled K-fold validation because groups are not passed to that function. In addition, the three base models used in the stacking regressor and the reported best improved model are selected using holdout MAE. Consequently, the grouped holdout prevents molecular overlap but is also used for model comparison; it is not a completely untouched final test after all model-selection decisions.

### 6.4 Validation-ready workflow and current held-out results

`validation_model.py` implements two protocols:

- `strict-grouped`: grouped 80:20 split, seed 42, with GroupKFold model selection;
- `paper-reproduction`: random 85:15 split, seed 1, with shuffled K-fold model selection.

The current saved validation model used `paper-reproduction`. The 354-row training partition and 63-row holdout were separated before candidate selection. The training script defaults to five-fold shuffled K-fold out-of-fold predictions for scoring, calibration, and model selection. Holdout labels were not used for that selection or calibration. The saved model bundle does not persist the actual `cv_folds` argument used for this run.

Because the split was row-random, 33 SMILES groups occur in both partitions and 54 of the 63 holdout rows have a SMILES also represented in training. The current results therefore estimate random-row holdout performance, not strict unseen-molecule performance.

## 7. Machine-Learning Models

### 7.1 Baseline models

The baseline track evaluates:

- multiple linear regression with 10 forward-selected features;
- Lasso regression;
- decision-tree regression;
- random-forest regression;
- gradient-boosting regression;
- XGBoost;
- CatBoost;
- LightGBM;
- RBF support-vector regression; and
- a feed-forward artificial neural network.

Linear models provide interpretable low-complexity references. Trees and random forests capture nonlinear thresholds and interactions. Gradient-boosting implementations were included because descriptor-response relationships may be nonlinear and heterogeneous. RBF-SVR provides a kernel-based nonlinear model. Lasso provides regularized linear shrinkage. The ANN provides a flexible high-capacity comparison.

The baseline ANN contains dense layers of 256, 128, 64, 32, 8, and 1 units, with dropout of 0.2 after the first four dense layers. It uses Adam with learning rate 0.0001, MAE loss, a maximum of 2,500 epochs, batch size 32, and early stopping with patience 150.

### 7.2 Benchmark models

The benchmark track evaluates Extra Trees, histogram gradient boosting, gradient boosting, random forest, ElasticNet, RBF-SVR, XGBoost, CatBoost, and LightGBM. The code also supports a RidgeCV stacking regressor and an arithmetic mean ensemble of strong tree-based models, although the current aggressive benchmark table contains the nine individual models.

### 7.3 Improved grouped models

The improved track evaluates MLR, Lasso, decision tree, random forest, gradient boosting, RBF-SVR, XGBoost, CatBoost, and LightGBM. A linear stacking regressor is fitted from the three individual models with the lowest grouped-holdout MAE.

### 7.4 Validation-ready candidates

The later holdout-validation workflow evaluates Extra Trees, random forest, gradient boosting with Huber loss, histogram gradient boosting, Extra Trees with a Yeo-Johnson target transform, and RBF-SVR. When optional libraries are installed, XGBoost, LightGBM, and CatBoost are added.

For every base model, a univariate linear calibration model is fitted using its training-only out-of-fold predictions. The four highest-ranked uncalibrated base models are also combined by a RidgeCV meta-model. Calibrated and uncalibrated single models and ensembles are compared using training-only out-of-fold R2.

## 8. Hyperparameter Optimization

The baseline uses predefined parameters rather than a general search, except for forward feature selection in MLR and early stopping in the ANN.

The benchmark track uses `RandomizedSearchCV`. The default configuration optimizes negative root mean squared error over repeated K-fold validation. Search spaces include tree counts, depth or leaf structure, learning rate, subsampling, feature subsampling, regularization, SVR `C`, `gamma`, and `epsilon`, correlation thresholds, and mutual-information feature counts. The current aggressive artifacts used one sampled combination per model and fixed override grids, so they represent a constrained search rather than the full 40-iteration default search.

The improved track also uses `RandomizedSearchCV`, with five-fold GroupKFold and negative MAE. The configured search examines:

- tree depth and minimum leaf size for decision trees;
- number of trees, depth, and minimum leaf size for random forests;
- number of estimators, learning rate, and depth for gradient boosting;
- `C`, `gamma`, and `epsilon` for RBF-SVR;
- Lasso regularization strength;
- estimator count, learning rate, and structural parameters for XGBoost, CatBoost, and LightGBM.

MLR is fitted without a hyperparameter search.

The validation-ready workflow does not use RandomizedSearchCV. It compares a predefined set of candidate specifications through out-of-fold predictions and then applies optional linear calibration and RidgeCV stacking.

## 9. Model Evaluation Metrics

The primary regression metrics are coefficient of determination, root mean squared error, and mean absolute error:

$$
R^2 = 1 - \frac{\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}
{\sum_{i=1}^{n}(y_i-\bar{y})^2}
$$

$$
\mathrm{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}
$$

$$
\mathrm{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
$$

Higher R2 and lower RMSE and MAE indicate better predictions. Baseline and improved outputs also include cross-validation MAE. Benchmark outputs include cross-validation or tuning RMSE and, when enabled, cross-validation MAE.

The common evaluation helper estimates a 95% percentile bootstrap interval for holdout MAE from 1,000 resamples. In the current aggressive benchmark run these intervals were skipped and stored as missing values.

Extended held-out QSAR/QSPR validation is implemented in `external_validation.py`. In addition to `R2_ext`, `RMSE_ext`, and `MAE_ext`, it calculates Q2_F1, Q2_F2, Q2_F3, Lin's concordance correlation coefficient (`CCC_ext`), squared Pearson correlation, Roy's direct and reverse r_m-squared measures, average and delta r_m-squared, origin-forced regression slopes and R-squared values, and the combined Golbraikh-Tropsha criteria.

For the regenerated 63-row random holdout, the saved principal results are `R2_ext=0.800009`, `RMSE_ext=0.459640`, `MAE_ext=0.288297`, and `CCC_ext=0.887728`. Direct `r_m^2=0.651599`, average r_m-squared `=0.724753`, and delta r_m-squared `=0.146308`; all 13 thresholded criteria pass. These values must be interpreted under the overlapping random-row split described above and do not establish strict unseen-molecule performance.

## 12. Applicability Domain and Robustness Analysis

The downstream DrugBank applicability domain is distance-based. A five-nearest-neighbor model is fitted to the 146-input experimental matrix. For each training and query compound, the mean distance to its nearest neighbors is calculated. The 95th percentile of the training mean-distance distribution is used as the applicability threshold:

$$
d_{\mathrm{query}} \leq Q_{0.95}(d_{\mathrm{training}})
$$

Compounds satisfying this rule are marked `within_domain=True`. The current DrugBank output classifies 736 of 2,293 compounds (32.1%) as within domain and 1,557 as outside domain. Distances in `analysis/applicability.py` are calculated on the supplied feature values without an internal scaling step; therefore, high-magnitude descriptors can dominate the distance measure.

Robustness analyses additionally include:

- 1,000-resample bootstrap intervals for holdout MAE in the common evaluation path;
- residual-versus-prediction, residual-distribution, and absolute-error plots;
- error summaries by quartiles of available molecular properties; and
- comparison of random-row and grouped-SMILES validation behavior.

Williams plots, leverage-based domains, standardized residual thresholds, Y-randomization, and learning curves are not implemented.

## 13. External Compound Prediction

### 13.1 DrugBank prediction

The DrugBank prediction workflow is implemented in `analysis/clustering.py`. It:

1. loads `drug_bank_clean.csv`;
2. obtains the exact 146 feature names from `clean_trial4.csv`;
3. assigns `Texpi=310` K;
4. orders DrugBank inputs to match the supervised feature schema;
5. loads a serialized model, optionally with a separate scaler;
6. predicts `predicted_logkpl`; and
7. saves predictions with chemical-space and applicability-domain results.

Because DrugBank has no experimental LogKp values, these predictions cannot be used to calculate supervised external-validation error.

### 13.2 RDKit-assisted prediction for unknown molecules

The later single-molecule workflow is implemented in `predict_logkp.py`, `src/skin_permeation/prediction.py`, and `scripts/render_rdkit_notebook.py`. For a user-provided SMILES:

1. RDKit parses the structure, rejects invalid SMILES, and returns a canonical SMILES.
2. RDKit calculates Crippen logP, molecular weight, topological polar surface area, hydrogen-bond acceptors and donors, rotatable bonds, and ring count.
3. The canonical SMILES and a user-specified `Texpi` value, defaulting to 310 K, are written to a temporary one-row copy of the original input schema.
4. Maven runs the same CDK 2.8 descriptor generator used for training, producing a training-compatible descriptor row.
5. The row is aligned to the 146-feature order from `clean_trial4.csv`.
6. `topoShape` is filled by its training mean; the named historical missing-value columns and any other absent numeric inputs are filled from training-derived means or medians.
7. Every compatible saved model is loaded and used to predict LogKp.
8. Per-model predictions, the canonical SMILES, RDKit summary descriptors, model paths, and a formula-based reference are saved to `reports/tables/unknown_compound_model_predictions.csv`.

RDKit is therefore used for structure validation, canonicalization, and a compact explanatory property panel. It does not replace the CDK feature panel required by the fitted models.

The formula-based comparison is the Potts-Guy expression:

$$
\log K_p = -2.72 + 0.71\log P - 0.0061MW
$$

The generated prediction plot labels this formula-derived value on the "actual" axis, but it is not an experimental measurement and should be described in reporting as a formula-based reference.

## 14. PCA, Clustering, and Chemical Space Analysis

### 14.1 DrugBank clustering

For clustering, identifiers and `predicted_logkpl` are removed, the remaining DrugBank descriptor matrix is standardized, and K-means models are evaluated for `k=2` through `k=10`. Each model uses 20 initializations and `random_state=1`. Inertia, silhouette score, and Calinski-Harabasz score are saved to `drugbank_cluster_selection.csv`.

The implemented final cluster count is fixed at four rather than selected programmatically from the best diagnostic value. The current cluster sizes are 950, 61, 982, and 300 compounds. Cluster summaries report the count, mean, standard deviation, minimum, and maximum predicted LogKp.

Two-component PCA is fitted to the standardized DrugBank descriptor matrix for visualization, and the coordinates are stored as `PCA1` and `PCA2`.

### 14.2 Experimental-versus-DrugBank chemical space

The publication-figure workflow separately identifies descriptors shared by the experimental and DrugBank tables. Missing values are imputed using medians fitted on the experimental data, scaling is fitted on the experimental data, and two-component PCA is fitted to the scaled experimental matrix. DrugBank compounds are then transformed into that training-defined PCA space. This analysis underlies `fig09_dimensionality_reduction`.

No UMAP or t-SNE analysis is implemented.

## 15. ATC, Drug-Class, or Group-Based Analysis

ATC analysis is implemented conditionally in `analysis/atc.py`, but no ATC mapping CSV or XLSX is present. Therefore, the ATC workflow has not been executed for the current repository outputs.

If a mapping is added, the code:

1. merges DrugBank predictions to the mapping by drug name;
2. truncates ATC codes to their first three characters;
3. retains ATC groups with at least three compounds;
4. summarizes count, mean, standard deviation, and median predicted LogKp;
5. performs a Kruskal-Wallis test across retained groups;
6. performs two-sided pairwise Mann-Whitney U tests; and
7. applies Benjamini-Hochberg false-discovery-rate correction with a significance threshold of 0.05.

In the absence of ATC labels, the current group-comparison figures use the four K-means clusters as the grouping variable.

## 16. Statistical Analysis

Pearson correlation is used for descriptor-correlation heatmaps and linear association with LogKp. Spearman rank correlation is also calculated for key descriptor-response plots.

For group comparisons, the general figure pipeline performs two-sided pairwise Mann-Whitney U tests for groups containing at least three observations and applies Benjamini-Hochberg FDR correction when `statsmodels` is available. The conditional ATC workflow additionally performs an overall Kruskal-Wallis test. The operational significance threshold is adjusted `p<0.05`.

The main command entry point is `scripts/run_full_pipeline.py`. Individual stages support data auditing, descriptor validation, baseline training, benchmark training, improved training, DrugBank clustering, ATC analysis, Java descriptor regeneration, and single-SMILES prediction. External-validation inputs and models are produced by `scripts/generate_external_validation_inputs.py` and `scripts/train_external_validation_model.py`. The command `scripts/validate_all_benchmark_models.py` clones each saved benchmark estimator, retrains it on the common validation-training partition, and evaluates all 11 models on the same frozen holdout without using holdout labels for fitting or tuning. Its result tables, prediction audits, retrained artifacts, and figures are written under `outputs/external_validation/benchmark_models/`. Tests under `tests/` cover data auditing, preprocessing, grouped splitting, validation-data generation, extended external metrics, validation-model behavior, all-benchmark validation, and inference alignment.

Reproducibility is limited by three repository-state issues that should be resolved before a final thesis submission: the exact historical descriptor-pruning sequence is not fully reproduced by the current function; the latest artifacts do not identify one consistent deployment model; and the saved DrugBank predictions do not match the current serialized model revisions. These limitations are documented explicitly rather than inferred from the reference paper.
